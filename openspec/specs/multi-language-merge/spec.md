# multi-language-merge

## Purpose

Combines the per-language subgraphs produced by multiple extractors into a single unified graph for repositories spanning more than one language.

## Requirements

### Requirement: MergeGraphs SHALL combine nodes and edges from multiple graphs
`MergeGraphs` SHALL accept a variadic list of `*graph.Graph` and return a single merged graph containing every node and every edge from each input graph. Empty input graphs SHALL be ignored without error.

#### Scenario: Nodes from all inputs present in merged graph
- **WHEN** `MergeGraphs` is called with two graphs, each containing distinct nodes
- **THEN** the merged graph contains every node from both input graphs

#### Scenario: Edges from all inputs present in merged graph
- **WHEN** `MergeGraphs` is called with two graphs, each containing distinct edges
- **THEN** the merged graph contains every edge from both input graphs, added best-effort (an edge referencing a missing node does not abort the merge)

#### Scenario: Empty graph ignored
- **WHEN** one of the graphs passed to `MergeGraphs` has no nodes and no edges
- **THEN** the merge proceeds normally using only the non-empty graphs, without error

### Requirement: Every extracted node SHALL carry a language property
Each node produced by a language extractor SHALL have its `Properties["language"]` set to that extractor's language, so nodes can be filtered by language in the frontend and in context generation after merging. This applies to every node type an extractor produces, including `ExternalDependency`, `Table`, and `Column` nodes, not only the primary language-native construct types (e.g. `Struct`, `Function`).

#### Scenario: Node tagged with source language
- **WHEN** the Java extractor produces a `Struct` node
- **THEN** that node's `Properties["language"]` SHALL equal `"java"`

#### Scenario: External dependency tagged with the extractor's actual language
- **WHEN** an extractor running in JavaScript mode (not TypeScript mode) produces an `ExternalDependency` node from a `package.json` dependency
- **THEN** that node's `Properties["language"]` SHALL equal `"javascript"`, not `"typescript"`

#### Scenario: Table and Column nodes tagged regardless of origin
- **WHEN** the Go extractor produces a `Table` or `Column` node, whether inferred from a struct tag or from a SQL migration
- **THEN** that node's `Properties["language"]` SHALL equal `"go"`

### Requirement: ID conflicts SHALL be resolved last-write-wins and reported
IDs are namespaced by import path/module, which naturally avoids conflicts between different languages' nodes. When two nodes of different types nonetheless claim the same ID (an intra-language collision, e.g. a same-named `Struct` and `Variable`), `graph.AddNode` SHALL register the conflict via `Graph.IDConflicts()`, and the merge SHALL apply last-write-wins semantics (the later-added node's data is retained) while surfacing a warning.

#### Scenario: Cross-language ID collision is not expected
- **WHEN** two extractors for different languages produce nodes for the same repository
- **THEN** their generated IDs SHALL NOT collide under normal operation, since each is namespaced by import path/module including a language-specific prefix or root

#### Scenario: Intra-language type collision recorded
- **WHEN** two nodes of different NodeTypes generated by the same extractor resolve to the same ID
- **THEN** `Graph.IDConflicts()` SHALL report the conflict, the later-added node SHALL win, and a warning SHALL be generated

#### Scenario: Empty graph does not trigger conflict warnings
- **WHEN** `MergeGraphs` merges a graph with no nodes into others
- **THEN** no ID conflicts are attributed to that empty graph

### Requirement: Package nodes SHALL remain distinct across languages sharing a namespace
When multiple languages produce `Package` nodes with similar names (e.g. a Java package and a TypeScript module with related naming), the merge SHALL keep them as separate nodes with distinct IDs rather than collapsing them.

#### Scenario: Similarly named packages across languages stay separate
- **WHEN** a Java package and a TypeScript module happen to share a similar name
- **THEN** the merged graph contains both as distinct `Package` nodes with distinct IDs

### Requirement: Cross-language edges are a non-goal of this phase
The merge SHALL preserve all nodes and edges produced by each per-language extractor as-is; it SHALL NOT attempt to infer or synthesize new edges connecting entities across different languages (e.g. a Java REST endpoint to a TypeScript fetch call).

#### Scenario: No inferred cross-language edge
- **WHEN** a repository has a Java backend and a TypeScript frontend with no explicit shared representation (e.g. no shared SQL table)
- **THEN** the merged graph contains no edge connecting a Java node directly to a TypeScript node beyond what each extractor independently produced
